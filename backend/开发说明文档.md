## 启动命令

> **重要**：所有 `from backend.xxx` 导入需要从项目**根目录**启动（`interview/`），不要 `cd backend` 后启动。

### 1. 环境准备

```bash
# 在项目根目录（interview/）下执行

# 创建虚拟环境
python -m venv .venv
source .venv/Scripts/activate   # Windows Git Bash
# 或 .venv\Scripts\activate     # Windows CMD

# 安装依赖
pip install -r backend/requirements.txt

# 配置环境变量（从模板复制并填入 LLM API Key）
cp .env.example .env
# 编辑 .env 填入真实的 LLM_API_KEY

# 回到项目根目录
cd ..
```

### 2. 开发模式启动

```bash
# 在项目根目录（interview/）下执行
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

启动后访问：
- API 文档（Swagger UI）：http://localhost:8000/docs
- 健康检查：http://localhost:8000/healthz

### 3. 生产模式参考

```bash
# 在项目根目录下执行
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --workers 1
```

> **注意**：当前 `workers=1` 是必须的——SSE 连接和会话状态存储在内存中，
> 多 worker 会导致状态无法共享和 SSE 连接路由错误。

### 4. 语法检查

```bash
python -m compileall backend
```

## API 概览

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/user/register` | 注册/登录用户 |
| `GET` | `/api/user` | 获取用户信息 |
| `POST` | `/api/practice/start` | 创建刷题会话 |
| `GET` | `/api/practice/:id/stream` | SSE 流式刷题 |
| `POST` | `/api/practice/:id/answer` | 提交刷题答案 |
| `POST` | `/api/practice/:id/next` | 请求下一题 |
| `GET` | `/api/practice/stats` | 刷题统计数据 |
| `POST` | `/api/interview/create` | 创建面试会话 |
| `GET` | `/api/interview/:id/stream` | SSE 流式面试 |
| `POST` | `/api/interview/:id/answer` | 提交面试回答 |
| `GET` | `/api/interview/:id/report` | 获取复盘报告 |
| `GET` | `/api/interview/:id/status` | 获取面试状态 |
| `GET` | `/api/history/practice` | 刷题历史列表 |
| `GET` | `/api/history/practice/:id` | 刷题会话详情 |
| `GET` | `/api/history/practice/stats` | 刷题统计 |
| `GET` | `/api/history/interview` | 面试历史列表 |
| `GET` | `/api/history/interview/:id` | 面试会话详情 |

所有需要用户身份的接口均需在 Header 中传入 `X-User-Id`。

## 说明

- 当前项目以单机单进程为主，SSE 和内存态会话状态都依赖单 worker。
- 如果后续改成多 worker，需要把会话状态从内存迁移到 Redis 等外部存储。
- LLM 客户端在未配置 `LLM_API_KEY` 时会自动使用 mock 回退，返回预设应答，方便开发调试。
- `requirements.txt` 已包含项目所需的基础依赖（含 loguru、ruff）。
