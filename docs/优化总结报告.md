## 1. 项目总览

### 1.1 一句话定位
> **AI 面试智能体** —— 基于 8 个专职 LLM Agent 编排的端到端面试闭环（JD 解析 → 简历匹配 → 动态出题 → 追问 → 四维评估 → 复习计划），**支持万人容量 / 百人并发**的企业级项目。

### 1.2 技术栈
- 后端：**Python + FastAPI + SQLAlchemy(asyncmy)**
- RAG：**bge-m3（1024 维）+ BM25(jieba) + RRF/score_norm 双融合 + bge-reranker-v2-m3 精排**
- 前端：**React 18 + Vite + Tailwind**
- 存储：**MySQL 8.0（生产）/ SQLite WAL（开发）**
- 缓存与队列：**Redis 7（限流 + 短期记忆 + 分布式锁预留）**
- LLM：**DeepSeek 官方 + 阿里云 MaaS 聚合端点**（多 provider 路由 + 熔断 + 降级链）
- 部署：**Docker Compose 一键起**（4 个服务 + 健康检查）

### 1.3 8 个 Agent
| Agent | 任务 | 主模型 |
|---|---|---|
| JDAnalyzer | 解析 JD → 结构化字段 | deepseek-flash |
| ResumeAnalyzer | 解析简历 → 技能画像 | deepseek-flash |
| QuestionPlanner | 按 JD+简历生成题目规划 | qwen3.8-flash |
| **Interviewer** | 出题 / 追问 / 点评 / 收尾 | deepseek-flash |
| Evaluator | 单题评分 + 总报告 | deepseek-flash |
| StudyPlanner | 错题入库 + 复习计划 | qwen3.8-flash |
| ChatAgent | 通用对话兜底 | qwen3.8-flash |
| IntentRouter | 意图分发 | 纯规则（零成本） |

### 1.4 多租户 / 计费
- **取消 BYOK**：服务端统一持有 LLM Key，按 provider 隔离
- **MAOO 平台适配层**：`PlatformAdapter` 协议 + Maoo/LocalDev 两实现，业务侧只与 `ResolvedUser` 接口交互
- **积分系统**：充值（mock + 幂等）→ 预扣 → LLM 调用 → 结算 → 不足返回 402
- **成本护栏**：`SpendLedger` 持久化流水 + 调用前硬校验，超限直接拒绝

## 2. v1 优化回顾（opt/v1，分支已合并）

| 模块 | 优化前 P0 | 优化后 |
|---|---|---|
| **网关/路由** | 全局单一 LLM Key，所有任务共用 | 多 provider 注册表 + 任务级路由 + 三态熔断 + 降级链 |
| **检索** | RRF 权重写死 0.6/0.4，无调参依据 | RRF + score_norm 双模式 + 权重网格搜索（实测最优 0.5/0.5）|
| **可观测** | 单一 `/health` | `/health/metrics`（5 类指标）+ `Meter` + trace + 成本折算 |
| **SSE** | 断连即丢事件 | 环形缓冲 + `Last-Event-ID` 回放 + seq 校验 |
| **会话锁** | 无锁（脏写） | `asyncio.Lock` + 快照 CAS |
| **难度自适应** | FSM 只写状态，出题仍用预设 | 难度由 FSM 实际裁决后注入 prompt |
| **向量字节序** | numpy 默认小端 → 索引静默变 inf/NaN | 显式 `>f4` 兼容历史 `>Nd` pack |
| **chunk id** | 向量与 BM25 用不同 key → RRF 融合失效 | 统一 `{doc_id}#{chunk_index}` |
| **积分** | 无（仅日预算） | 预扣/结算/退回/充值占位 + 幂等 |

**v1 测试**：6 → 43 passed（覆盖全部 P0 缺陷）

## 4. M1：BYOK 移除 + 平台用户 + 积分

### 4.1 决策背景
用户明确：**不再使用 BYOK（用户自带 LLM Key）**，改为平台提供 key、用户充值积分。

### 4.2 代码改动
| 文件 | 改动 |
|---|---|
| `backend/app/llm.py` | 删除 `llm_api_key_ctx` / `set_llm_key_context` / BYOK 取 key 路径 |
| `backend/app/deps.py` | 移除 `X-LLM-Key` 头解析 |
| `backend/app/routers/auth_router.py` | 删除 `POST /auth/test-llm` |
| `frontend/src/api/client.ts` | 不再发 `X-LLM-Key` 头 |
| `frontend/src/pages/Profile.tsx` | 删除「自带 API Key」输入卡 |
| `backend/app/platform/maoo.py`（新增） | `PlatformAdapter` 协议 + Maoo/LocalDev 两个实现 + `resolve_chain` |
| `backend/app/platform/__init__.py`（新增） | 包初始化 |

### 4.3 平台适配层（关键设计）
业务侧**只与 `ResolvedUser` 接口交互**：
```python
# 业务代码示例
user = await resolve_chain(request.headers)  # 自动从 MAOO 头解析
if user is None: raise HTTPException(401)
# ↓ 业务侧完全不知道这是 MAOO 还是 Keycloak 还是自己开发
```

未来换 SSO / OAuth2 / 自研用户系统：业务代码零改动，只换一个 `PlatformAdapter` 实现。

### 4.4 积分系统增强
- **预扣 → 结算**：LLM 调用前按预估 token 预扣，调用结束按实际 token 结算（多退少补）
- **幂等键** `(request_id, kind)`：同一请求重试只扣一次
- **402 状态码**：余额不足时统一返回 `Payment Required`，前端自动跳充值页
- **充值幂等**：`order_id` 留作真实支付回调的幂等键（目前 mock，但接口已就绪）

### 4.5 测试覆盖（10 个新增）
```python

test_byok_no_x_llm_key_header   # 后端不再解析 X-LLM-Key
test_no_user_api_key_settings   # 前端 Profile 页不再有 API Key 输入
```

## 5. M2：企业级架构骨架

### 5.1 目标
> **百人并发 / 万人容量** —— 撑得住的真实部署形态

### 5.2 三大支柱

#### (1) Redis 限流（`app/ratelimit/sliding_window.py`）
- **Lua 脚本保证原子性**：多 worker 进程不竞态
- **三档桶**：全局 500 QPS / 每用户 20 QPS / 每 IP 50 QPS
- **滑动窗口算法**：当前窗口 + 上一窗口加权（O(1) 内存、O(log N) 时间）
- **降级放行**：Redis 故障时不限流（业务优先）

```lua
-- 简化版 Lua（实际脚本见 app/ratelimit/sliding_window.py）
local now = redis.call('TIME')
local key = KEYS[1]; local limit = tonumber(ARGV[1])
local cur_window = math.floor(now[1] / ARGV[2])
local prev_window = cur_window - 1
-- 用 ZADD/ZREMRANGEBYSCORE 维护当前窗口
-- 加权计算：prev_count * (1 - elapsed/window_size) + cur_count
-- 超 limit 则返回 0
```

#### (2) 异步任务队列（`app/queue/asyncio_queue.py`）
- **10 优先级桶** + 8 worker 协程（`asyncio.Semaphore` 等价）
- **Task dataclass**：含优先级/超时/用户 id/request id
- **`register()` 装饰器注册 handler；`enqueue()` 入队**
- **失败/超时单独统计**；日志记录 traceback

适用场景：批量报告生成、错题本异步入库、文档批量审核等可延迟任务。

#### (3) MySQL 连接池（`app/database.py`）
```python
engine = create_async_engine(
    url, pool_size=20, max_overflow=40,
    pool_recycle=3600, pool_pre_ping=True,
)
```
**为什么 pool_size=20**：FastAPI 是单进程异步模型，每个请求通常持有连接几十~几百 ms；
20 个连接 + 40 overflow 在百人并发下足够（连接池等待队列由 asyncmy 内部维护）。

### 5.3 多实例部署（`deploy/gunicorn.conf.py`）
```python
workers = multiprocessing.cpu_count() * 2 + 1
worker_class = "uvicorn.workers.UvicornWorker"
max_requests = 1000              # 每处理 1000 请求优雅重启（防内存累积）
max_requests_jitter = 50         # 错峰
timeout = 120                    # LLM 调用可达 60s，留 2 倍缓冲
```

**为什么用 uvicorn worker 而非 sync worker**：FastAPI 是 ASGI 应用，
原生支持 asyncio；sync worker 会阻塞事件循环，无法发挥 FastAPI 性能。

### 5.4 压测脚本（`bench/stress_test.py`）
- 100 并发协程 + 60 秒持续请求
- 输出 RPS / P50 / P95 / P99 / 错误率
- 用于 CI 持续监测容量曲线

## 7. M4：出题/追问质量评测（LLM-as-judge）

### 7.1 评测设计

**Judge 模型**：服务端 deepseek-flash（思考模式禁用 + 显式 retry）

**样本规模**：
- 出题 19 条（覆盖 8 学科 × easy/medium/hard × concept/code/scenario 题型）
- 追问 8 条（基于真实"错答 + 遗漏点"构造）

**评测维度**（每维 0/1/2 评分）：

出题质量：
- `topic_relevance` — 是否围绕主题
- `difficulty_fit`   — 难度（初/中/高）匹配
- `clarity`         — 口语化、清晰
- `groundedness`    — 引用检索到的真实知识
- `type_fit`        — 题型（concept/code/scenario）匹配
- `answer_leak`     — 不直说答案

追问质量：
- `targeted` — 针对遗漏点
- `depth`    — 深挖而非换角度
- `brevity`  — ≤ 80 字
- `natural`  — 不重复原题

### 7.2 评测结果

**出题质量（满分 2.0）**：

| 维度 | 平均分 | 解读 |
|---|---|---|
| topic_relevance | 2.00 | 围绕主题 ✅ |
| difficulty_fit | 2.00 | 难度匹配 ✅ |
| clarity | 2.00 | 口语化清晰 ✅ |
| **groundedness** | **1.47** | **参考资料引用不足 ⚠️** |
| type_fit | 1.95 | 题型匹配 ✅ |
| answer_leak | 2.00 | 无答案泄露 ✅ |

**总评：1.90 / 2.0**

**追问质量（满分 2.0）**：targeted=2.0 / depth=1.88 / brevity=2.0 / natural=2.0
**总评：1.97 / 2.0**

### 7.3 已知弱点 + 下一步
- **groundedness 仅 1.47**：出题时没有把检索到的参考资料注入 prompt
- **改进方向**：把 `search_for_agent` 返回的 top-3 拼接进 ASK_PROMPT，让 LLM 基于真实术语出题

### 7.4 评测基础设施
- 平衡花括号 JSON 解析器（容忍提示词中含 `{}` 占位符的边界 case）
- 思考模式 retry（DeepSeek V4 有时会无视 `extra_body`，强制显式重试一次）

## 12. 名词表

> 给初学者的解释见 `docs/名词解释.md`（独立单册）

| 术语 | 一句话解释 |
|---|---|
| BYOK | Bring Your Own Key，用户自带 LLM Key。本项目已取消。 |
| MAOO | 用户当前的部署平台（maoojjkk.xyz），用户系统在此托管 |
| LLM | 大语言模型。本项目用 DeepSeek V4 Flash / Qwen3.8 系列 |
| Embedding | 把文本转成 1024 维向量，使计算机能算语义相似度 |
| Rerank | Cross-Encoder 精排，对 (query, 候选) 重新打分，比双塔向量更准 |
| RAG | Retrieval-Augmented Generation，检索增强生成。先查资料再让 LLM 答 |
| BM25 | 经典关键词检索算法，基于 TF-IDF 思想 |
| RRF | Reciprocal Rank Fusion，多路检索结果的融合算法（按名次倒数求和）|
| score_norm | 另一种融合方式（把每路分数归一化到 [0,1] 后加权）|
| LLM-as-judge | 用 LLM 当裁判，给模型输出打分 |
| JWT | JSON Web Token，登录后服务端签发的身份凭证 |
| SSE | Server-Sent Events，单向服务器推送（流式响应）|
| asyncio | Python 原生协程库，单线程实现高并发 |
| contextvars | asyncio 的请求级隔离机制（每个请求一个独立 dict）|
| SQLite WAL | SQLite 的预写日志模式，并发读不阻塞写 |
| Pool | 数据库连接池，避免每次都新建连接 |
| Sentinel | Redis 高可用方案（master + 多 slave 自动切换） |
| HNSW | Hierarchical Navigable Small World，近似最近邻搜索算法 |
| pytest | Python 最流行的测试框架 |
| pydantic | Python 数据验证库（FastAPI 用它做请求/响应模型）|
| FastAPI | 现代 Python Web 框架，原生异步 + 自动 OpenAPI 文档 |
| React | Meta 出品的 UI 框架 |
| Vite | 新一代前端构建工具（比 Webpack 快）|
| Tailwind | 原子化 CSS 框架 |
| Docker | 容器化引擎，把应用 + 依赖打包成镜像 |
| docker-compose | Docker 的多容器编排工具 |
| Mock | 测试时替代真实组件的桩（用确定性输出代替副作用）|
| Idempotency | 幂等性，同样的请求执行多次效果相同（扣费只扣一次）|
| Type Hints | Python 类型注解（`def f(x: int) -> str`）|
