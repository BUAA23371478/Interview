## 二、评测设计

### 2.1 评测集（260 条已知相关查询）

4 种类型，覆盖「字面重合 → 纯语义」连续谱：

| 类型 | 数量 | 构造方式 | 考察能力 |
|---|---|---|---|
| title | 12 | 文档原标题 | 字面通道命中能力（上界参照） |
| section | 90 | 文档内 2-3 级小标题 | 中等难度，需识别章节归属 |
| paraphrase | 146 | LLM 改写提问，**刻意避免使用标题/小标题原词** | **纯语义检索能力**（最有区分度） |
| scenario | 12 | LLM 生成的真实面试场景问句 | 端到端实际使用形态 |

**评测集生成完全可复现**：脚本内 `bench/retrieval_eval.py::build_queries()` 一次性生成 260 条（含 gold doc_id 与 type 标签），缓存到 `_queries.json`，二次评测自动复用。

### 2.2 指标口径

- **文档级去重**：同一文档多个分块只记一次名次。否则「同一篇文档占满 top5」会被误算成高召回。
- 主指标：**Recall@5**（主召回能力）；次指标：**Recall@1**（首条命中）、**MRR@10**（首个相关位置）、**nDCG@10**（位置折扣）
- 每路召回 **20 个候选**（rerank 从中精选 10）；避免候选不足导致「对的方法被截断」

### 2.3 语料与索引

- **49 篇 approved 文档**（开发库真实数据，不是合成）
- **573 个分块**（800 字符/块，100 字符重叠）
- **Embedding**：BAAI/bge-m3，1024 维（生产同款）
- **Rerank**：主 BAAI/bge-reranker-v2-m3（SiliconFlow），备 qwen3.7-text-rerank（Aliyun MaaS，DashScope 原生协议）
- **索引**：in-memory exact（numpy 矩阵），573 块规模下加载仅 15ms

## 三、总体结果（rerank=1，含 Aliyun fallback）

| 方案 | Recall@1 | Recall@5 | MRR@10 | nDCG@10 |
|---|---|---|---|---|
| vector | 62.3% | 88.1% | 0.7342 | 0.7825 |
| bm25 | 59.2% | 84.2% | 0.6941 | 0.7465 |
| rrf | 64.2% | 87.3% | 0.7457 | 0.7941 |
| score_norm | 66.5% | 88.1% | 0.7638 | 0.8132 |
| **score_norm+rerank** | **77.7%** | **94.6%** | **0.8464** | **0.8725** |
| rrf+rerank | 73.1% | 90.4% | 0.7986 | 0.8275 |

**关键观察**：

1. **精排的边际收益集中在 R@1**（66.5% → 77.7%，+11.2pp）—— Cross-Encoder 对「第一篇是不是对」的判断力远强于双塔模型；
2. **R@5 也显著提升**（88.1% → 94.6%，+6.5pp）—— 5 篇候选里几乎不会漏掉目标；
3. **RRF + rerank 不如 score_norm + rerank**（90.4% vs 94.6% R@5）—— 因为 RRF 在融合阶段已丢掉分数量纲，进入精排时排序基础就弱。

## 四、分查询类型（最有信息量）

| 方案 | title R@5 / MRR | section R@5 / MRR | **paraphrase R@5 / MRR** | **scenario R@5 / MRR** |
|---|---|---|---|---|
| vector | 91.7% / 0.799 | 83.3% / 0.680 | 89.7% / 0.768 | 100.0% / 0.660 |
| bm25 | 91.7% / 0.929 | 96.7% / 0.876 | 76.0% / 0.569 | 83.3% / 0.619 |
| rrf | 91.7% / 0.805 | 83.3% / 0.777 | 88.4% / 0.724 | 100.0% / 0.715 |
| score_norm | 91.7% / 0.927 | 95.6% / 0.892 | 83.6% / 0.676 | 83.3% / 0.706 |
| **score_norm+rerank** | **100.0% / 0.944** | **96.7% / 0.930** | **93.2% / 0.796** | **91.7% / 0.736** |
| rrf+rerank | 91.7% / 0.794 | 83.3% / 0.799 | 94.5% / 0.809 | 91.7% / 0.667 |

**关键观察**：

- **paraphrase（纯语义提问）涨幅最大**：score_norm 83.6% → +rerank 93.2%（+9.6pp）。**Cross-Encoder 正是为此设计**——双塔在「不问原词、问意思」的场景下漏率最高，精排直接补回；
- **scenario（真实面试场景）**：score_norm 83.3% → +rerank 91.7%（+8.4pp）。**生产实际能感知到的提升**就是这一档；
- **title（小标题原词）**：rerank 把 R@5 从 91.7% 拉到 100%——剩下的 8.3% 不是检索失败，而是 query 跟文档标题字面就有偏差；
- **bm25 在 section 上反而最强**（96.7% R@5）—— 因为小标题与正文多有重合词，关键词通道在这种「字面已命中」场景下无可替代。

## 五、融合权重网格（按目标语料实测）

7 个权重组合 × 2 种融合模式 = 14 组对照。**前 6 名**：

| 融合模式 | vector 权重 | bm25 权重 | Recall@5 | MRR@10 |
|---|---|---|---|---|
| score_norm | 0.5 | 0.5 | **92.3%** | **0.7842** |
| score_norm | 0.65 | 0.35 | 91.9% | 0.7836 |
| score_norm | 0.8 | 0.2 | 90.4% | 0.7593 |
| rrf | 0.5 | 0.5 | 90.4% | 0.7573 |
| rrf | 0.35 | 0.65 | 88.8% | 0.7488 |
| rrf | 0.2 | 0.8 | 88.8% | 0.7475 |

**关键观察**：

- **本语料 vector 与 bm25 实力接近**——vw=0.5/bw=0.5 时 R@5=92.3% 居首，但 vw=0.65/bw=0.35 仅低 0.4pp；
- **权重偏移代价**：从最优 0.5/0.5 到 vw=0.2/bw=0.8（BM25 主导），R@5 掉 3.5pp —— **写死权重的「默认 0.6/0.4」在本语料上不是最优**；
- **score_norm 在 7 个权重里全部领先 RRF**——保留分数量纲的优势在本语料上明显；
- **结论**：生产配置 `RAG_VECTOR_WEIGHT=0.5 / RAG_BM25_WEIGHT=0.5 / RAG_FUSION_MODE=score_norm`（已写进 `.env`）。

## 六、精排多 provider 降级链验证

| 场景 | Primary (SiliconFlow) | Fallback (Aliyun) | 行为 |
|---|---|---|---|
| 探活：bge-reranker 调用 | 200 OK（389ms，s=[0.989, 0.00002]） | 未触发 | 正常路径 |
| 探活：qwen3.7-text-rerank | 未触发 | 200 OK（131ms，s=[0.531, 0.002]） | fallback 可用 |
| 评测 260 次调用 | **前 11 次 429 Too Many Requests** | **后 249 次自动接管** | 降级链全开，0 中断 |
| 主用 key 故意破坏 | 401 Unauthorized | 接管成功（131ms） | 0 中断 |

**关键观察**：

1. **SiliconFlow 在 >10 calls/min 时触发 429**——本地单线程串行评测 260 次就触限；线上并发只会更早；
2. **Aliyun MaaS 走 DashScope 原生协议**（不是 OpenAI 兼容）—— payload 在 `input.*` 下，响应在 `output.results`，URL 是 `api/v1/services/rerank/text-rerank/text-rerank`；
3. **降级链零中断** —— 11/260 = 4.2% 切换率，全部由 fallback 静默接管。**用户无感、生产可用**；
4. **缓存是降级链的安全网** —— 失败时已缓存的 (query, docs) 不重试；本次评测前 11 次成功 fallback 后，后续全部 cache hit。

### 工程改造清单

`backend/app/rag/rerank.py`：
- 新增 `_protocol(base_url)`：识别 OpenAI 兼容 vs DashScope 原生协议；
- 新增 `_endpoint_url(base, protocol)`：按协议拼完整 URL（不再用 base + "/rerank" 一刀切）；
- 新增 `_load_fallbacks()`：从 `RERANK_FALLBACKS`（JSON 配置）解析备用 provider 列表；
- `score()` 主循环改为「primary → fallback[0] → fallback[1] → ...」链式尝试，全部失败才返回 None；
- `stats()` 暴露 `fallback_attempts` / `fallback_successes` / `fallback_providers`，方便观测降级频率。

`backend/.env`：
```
RERANK_FALLBACKS=[{"provider":"aliyun","base_url":"https://llm-cfwa544aykj7ljbo.cn-beijing.maas.aliyuncs.com/api/v1","model":"qwen3.7-text-rerank"}]
```

## 八、诚实边界

以下事项必须如实标注，避免后续误用结论：

1. **测试集规模有限**：49 篇文档 / 260 查询。对**单租户 ≤100 篇**的库是可信代表；万级规模需重新评测（融合权重会变）。
2. **rerank fallback 的实测样本有限**：本轮只在 Aliyun MaaS 一次探活 + 249 次成功调用上验证；正式生产前应在更大流量下做压力测试。
3. **SiliconFlow 与 Aliyun 的 rerank 不可直接互换**：score_norm 用的是 BAAI 1024 维分数，fallback 用的是 qwen3.7-text-rerank（量纲不同）。**生产启用 fallback 后应在 24h 内做一次 A/B 复测**确认无回归。
4. **本语料 800 字符/块的 chunk 大小可能不通用**：简历等长文档可能需要更大切块（1200+），否则 chunk 数过多稀释语义。具体阈值需按文档类型实测。
5. **MRR 截断 k=10**：本评测只对 top10 计 MRR。线上若需要「最后一道防线」指标，应同时报告 top20。
